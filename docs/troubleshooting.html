Troubleshooting

Common problems and what to do about them. If something here doesn't help, open an issue with codec version and what you saw.

Starting codec#

Windows says "Windows protected your PC"#

The binary isn't code-signed. Choose More info → Run anyway, or unblock it once in PowerShell: Unblock-File .\codec.exe. No admin rights are needed.

macOS won't open it#

Gatekeeper blocks unsigned downloads. Remove the quarantine flag: xattr -d com.apple.quarantine codec.

"port 8765 is already in use"#

Another codec (or something else) is using the port. Stop it, or start on another port: codec serve --port 8766.

"codec restarted" or "can't reach the server"#

Each run of codec serve uses a new security token, so a page opened before a restart can't talk to the new run. codec notices and shows a codec restarted — Reload banner; reload and your tabs and layout come back. "Can't reach the server" means codec isn't running: start it again.

Desktop app#

  • No tray icon: Windows hides new tray icons behind the ^ arrow; drag it onto the taskbar to keep it in view.
  • Closing the window doesn't quit: by design, codec stays in the tray. Quit from the tray menu, or turn off Settings → Desktop → Keep running in the tray.
  • Display preferences reset: the desktop app uses port 8769 so its window keeps the same storage. If something else holds that port, codec starts on a free one with fresh preferences for that run; free the port and restart.
  • The window stays blank: the app needs Microsoft Edge WebView2, part of Windows 11. On older Windows, install the WebView2 Runtime from Microsoft.
  • Start at login points to an old place: it records where the exe was when you turned it on. After moving it, turn the setting off and on again.

Files and folders#

A file isn't in the explorer#

  • It is ignored by a .gitignore, or it's inside .git, node_modules or a similar folder.
  • It is larger than 8 MB, or it looks binary.
  • The folder has more than 50,000 files: the tree is cut and says so. Open a sub-folder instead.
  • It is behind a symlinked folder, which codec doesn't follow.

Changes on disk don't show up#

codec uses native file events and falls back to polling when they fail. Some setups report events unreliably (network drives, WSL paths, Docker bind mounts); start with --poll to force polling. The dot next to the folder name in the status bar shows the watch mode (hover it for details).

A huge file is slow#

Files up to 8 MB are supported: typing stays responsive and analysis runs a little later than usual. The outline of very large files keeps fewer levels (it says so). Files over 8 MB are not opened.

Schemas#

"Downloading the schema…" doesn't go away#

codec couldn't reach the schema sources. Behind a corporate proxy, set HTTPS_PROXY before starting codec (it follows the standard proxy variables). On a machine without internet, turn on Offline in Settings and point Custom schema folder at a copy of codec's schema cache from another machine, or at your own schemas.

"No schema is published for …"#

The CRD isn't in the public catalog. Put its JSON schema in your custom schema folder as <group>/<kind>_<version>.json (for example example.com/widget_v1.json).

Lens views#

Helm: "missing dependency"#

codec never downloads. Run helm dependency build once (outside codec) so subcharts are in the chart's charts/ folder, or vendor them there.

Kustomize: remote bases or helmCharts#

Remote bases (git or http URLs) aren't fetched, and helmCharts would need the helm binary. Use a local copy of the base, and render charts in the Helm view.

CI: an include or template "doesn't exist"#

Local includes are resolved from the repository root. In the UI that is the open folder; on the CLI it is the folder holding .git. If you run the CLI from inside a bigger repository, pass --root. Remote includes are listed as "not read" by design.

Ansible: a role is "not found"#

codec looks in roles/, roles_path from ansible.cfg and folders up to the repository root. Roles installed from Galaxy or collections at run time can't be read; codec notes that rather than failing.

Open in VS Code does nothing#

The button uses the vscode:// (or cursor://) link your editor registers when installed normally. Portable installs may not register it. Check that the right editor is chosen in Settings; the first time, your browser asks whether to open the editor — allow it.

Docker#

  • The page doesn't load: the container listens on 8765 inside; open the host port you published (-p 127.0.0.1:8765:8765 → localhost:8765).
  • Profiles and schemas are gone after a restart: add -v codec-home:/home/nonroot.
  • Files outside /work: only mounted folders are visible; mount the repository you want.

Starting over#

Delete (or rename) the settings file shown in Settings → Folders to reset every setting; clear the site data for localhost:8765 in your browser to reset the layout and tabs. The schema cache can be deleted at any time.
