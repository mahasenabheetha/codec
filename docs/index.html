codec

The local workbench for a DevOps engineer's day: read and check the YAML you live in — Kubernetes, Helm, Kustomize, Argo, CI pipelines, Compose and Ansible — make sense of pipeline logs, and handle the tokens, hashes, timestamps, cron schedules and regexes around them. One binary, a local web UI and a CLI, next to your editor. Nothing leaves your machine.

Windows · macOS · Linux · Docker No install, no admin rights Never writes to your files Nothing leaves your machine

Why codec#

Most of a platform engineer's day is spent reading YAML: what does this chart render with the prod values, which job runs after which, where is that Ansible variable really set, what does this Argo step get as input. The answers usually need a cluster, a pipeline run, or a lot of scrolling. codec answers them from the files alone, on your machine, without changing anything.

  • Understand, don't just edit. Every lens shows the file the way the tool that runs it sees it: Helm's merged values, GitLab's effective job after extends, Compose's merged services, Ansible's execution order.
  • Try things safely. Edits in codec are what-if: they change what you see, never the file. Copy the result or a git apply patch when you like it.
  • Explain every problem. Each finding says why it matters and how to fix it, and points to the exact line.
  • Stay next to your editor. "Open in VS Code / Cursor" jumps to the same file and line. codec is a companion, not a replacement.

What it does#

▤

Workspace and editor

Open a repo read-only, every YAML file labelled by type, a template-aware editor with hover, outline and plain-English errors.

 ⎈

Helm

Render charts exactly like helm template, with no helm install. See where every value came from.

 ✓

Lint and schemas

YAML traps, risky Kubernetes settings, removed APIs and schema validation for Kubernetes, CRDs and CI files.

 ⬡

Kubernetes and Kustomize

Objects as cards, a relationship graph, an inventory and broken references. Kustomize builds without kubectl.

 ⟿

Argo

Workflows as graphs with every step's template and inputs resolved, across files. Argo CD apps rendered with their values.

 ⑂

CI pipelines

GitHub Actions, GitLab CI and Azure Pipelines in execution order, with each job's effective configuration and where each line came from.

 ▣

Compose

Files merged like docker compose config, variables from .env, services as a graph, ports and volumes.

 ☰

Ansible

Playbooks in the order Ansible runs them, roles opened in place, variables ranked by precedence, inventories, and a playbook map coloured by a run.

 ⇄

Compare and query

Diff by meaning (key and list order ignored), dev vs prod renders, and jq over the whole repo.

 ＋

New files and clones

Starters with a short form, checked before you copy them; clone a file under a new name, references and all.

 ⌘

Everyday tools

Smart paste, base64, JSON, JWT and Ansible logs; URL, hex, hashes, secrets and htpasswd; timestamps and cron in plain words; a regex tester that explains the pattern.

 >_

CLI

The same engine from the terminal and in CI, with exit codes that work as gates.

Try it in a minute#

  1. Download the archive for your platform from GitHub Releases and unpack it.
  2. Run codec serve --open --sample. Your browser opens codec on a small made-up repository.
  3. You land on its Helm chart, rendered. Add values-prod.yaml, hover a value, open the other views from the sidebar or with Ctrl K.

When you're ready, open your own repository with Ctrl O or codec serve --root path/to/repo. Getting started has the details for every platform and Docker.

Principles#

PrincipleWhat it means in practice
Read-onlycodec never writes to the folders it opens. Settings live in your user profile; generated files are text to copy or a zip your browser saves.
LocalThe server listens on 127.0.0.1 only, with a per-run token. The only network use is downloading public JSON schemas, which you can turn off.
FaithfulHelm renders with the real Helm SDK, Kustomize with the real kustomize library. Where codec reimplements a tool's rules (Compose merging, GitLab extends, Ansible precedence) it follows the documented behaviour and says what it can't know.
Honest about run timeValues only known when something runs (step outputs, cluster lookups) stay as written and are marked, never guessed.
FastDesigned for 10,000-file repositories and files up to 8 MB. See performance.
