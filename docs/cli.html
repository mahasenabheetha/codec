CLI reference

The web UI and the CLI share one engine, so everything codec understands is available in a terminal and in CI. codec <command> --help prints the same details with examples.

Conventions#

  • Output: data on standard output, notes and warnings on standard error — safe to pipe.
  • Input: commands that take a file also read standard input when the file is omitted (helm template ./chart | codec k8s refs).
  • Exit codes: 0 ok; 1 error or bad usage; 2 findings (lint problems, differences, broken references, pipeline or workflow problems) — so every checking command works as a CI gate.
  • JSON: most commands take --json for machine-readable output.
  • Read-only: no command modifies files. Commands that make files (new, clone, fmt) print them.
  • -c / --copy on any command also copies the output to the clipboard.

Lint#

CommandFlags
yaml lint [path…] — files and folders (honouring .gitignore); default .--k8s-version 1.30…1.37 · --offline · --no-schemas · --json

Rule levels come from your settings (see Lint and schemas). Exit 2 when there are warnings or errors.

.github/workflows/lint.yml (excerpt)
- name: Lint YAML
  run: |
    curl -sSL https://github.com/mahasenabheetha/codec/releases/download/v2.0.0/codec_2.0.0_linux_amd64.tar.gz | tar xz codec
    ./codec yaml lint deploy/ charts/ --k8s-version 1.31

Helm#

CommandWhat it does
helm render <chart-dir>Like helm template, manifests to stdout
helm values <chart-dir>Merged values; --provenance annotates each with the layer that set it

Shared flags: -f/--values (repeatable, later wins) · --set (repeatable) · --release · -n/--namespace · --kube-version · -a/--api-versions · --include-crds. Dependencies must be vendored in charts/.

CI pipelines#

CommandWhat it does
ci jobs <file>Stages and jobs in execution order; exit 2 on problems
ci job <file> <job>One job's effective configuration, each line's origin
ci graph <file>Jobs as a diagram (--format mermaid|dot)

Shared flags: -p/--input name=value (workflow inputs, template parameters) · --root (repository root for includes; default the folder holding .git) · --json.

Compose#

CommandWhat it does
compose services [files…]Services with ports, volumes and start order, plus variables
compose config [files…]Merged configuration, the file per line

Without files, the default project files of the current folder are used. Flags: -e NAME=value (wins over .env) · --env-file FILE (none for no file) · --json. Your shell's environment is not read.

Ansible#

CommandWhat it does
ansible plays <playbook>Plays and tasks in execution order
ansible vars <playbook> [name]Where variables are defined, highest precedence first
ansible task "<name from a log>"Find a logged task's definition (--path takes the log's "task path")
ansible inventory <file>Groups and hosts
ansible log <file|->A whole pipeline log: runs, failures with their reason and file, recap, other output with errors (--all every task, --json); exit 2 when the log shows a failure

Flags: --root (repository root for roles) · --json.

Encode and hash#

CommandWhat it does
url encode|decode [text]Percent-encoding; --whole keeps a URL's structure, --plus treats a space as +
url parse [url]A URL's parts and its query string as a table (--json); a bare a=1&b=2 works too
hex encode|decode [text]--upper, --sep :; decoding accepts spaces, colons, 0x and \x
hash [text]SHA-256, SHA-384, SHA-512, SHA-1, MD5 of the exact bytes (-a sha256 prints only that digest, --base64); --hmac-key-env VAR for HMACs
secretRandom secrets: --length, --sets lower,upper,digits,symbols, --format hex|base64|base64url, --no-ambiguous, -n
uuidRandom UUIDs (version 4), -n for more than one
htpasswd <user>A bcrypt user:hash line for basic auth; the password is asked for or piped in (--cost). --check "<line>" checks one, exit 2 when it doesn't match
