Everyday tools

The tools for the text you handle all day: smart paste, base64, JSON & YAML, JWT and Ansible logs, and under Utilities URL and hex encoding, hashes, secrets, htpasswd lines, CIDR ranges and IP addresses, CSV and TSV tables, timestamps, cron schedules and regular expressions. They work without an open folder, and nothing you paste is stored or sent anywhere.

Smart paste#

Smart paste and Base64 have tabs, like the Log viewer: keep a JWT, a base64 secret and a JSON blob open at once, each with its own input and result. + (or Alt T) opens a tab, × or a middle click (or Alt W) closes one, a double click renames it. Smart paste names a tab after what it found (JWT, base64, JSON); Base64 after its direction (Encode 1), never after what you pasted. Closing a tab with text in it offers Undo; tabs last as long as the window.

Every tool's output has a Find button (or Ctrl+F with the pointer over the output): type and every match is marked, with a count; Enter goes to the next, Shift+Enter to the previous. Case is ignored.

Paste anything. codec detects JSON, base64, a JWT or an Ansible log and does the obvious thing: pretty-prints JSON, decodes base64 (and pretty-prints it if the result is JSON), decodes a token, analyses a log. An epoch timestamp, URL-encoded text or a cron expression is read too, with a button to open it in Timestamp, URL or Cron; a CIDR range, an IP address or a curl command is described or converted, with a button to open it in the Network tool (a bare number is never taken for an address); a structured log is summarised, with a button to open it in the Log viewer. JSONC or JSON5 (an object or array with comments, trailing commas or unquoted keys) is written as JSON, with a button to open it in JSON & YAML; CSV or TSV (three lines or more, every row as wide, short cells) is described column by column, with a button to open it in CSV & TSV. A UUID (hyphenated, in braces or as urn:uuid:) or a ULID is read for its version and time, with a button to open the UUID tab; a hex colour (#4f46e5, with the #) is shown as RGB and HSL, with a button to open Colour. The status bar says what it detected.

Base64#

  • Encode or decode, standard or URL-safe alphabet.
  • Decoding tolerates missing padding and whitespace — handy for values copied out of Kubernetes Secrets.
  • Decoded JSON is pretty-printed, numbers kept exactly. Turn Pretty JSON off to see the bytes exactly as decoded.
  • Decoded JSON is pretty-printed.
  • Swap (Alt S) moves the output to the input and flips encode/decode.

JSON & YAML#

Paste a document once and look at it every way: Format, Tree, Paths, Schema and Query share it. Several documents can be open at once, each in a tab of its own below the toolbar: + (or Alt T) for a new one, × or a middle click (or Alt W) to close, a double click to rename. Each keeps its own inputs (Diff's two sides, the Query filter, Convert's YAML and Paths' lines) and comes back on the view you left it on; indentation and sorting are shared. A tab is named after a Kubernetes-shaped document (Deployment/api), else Document 1; closing one with text in it offers Undo. JSONC or JSON5 opened from Smart paste goes into the current document when it is empty, otherwise a new one. JSONC (comments, trailing commas) and JSON5 (unquoted keys, single quotes, hex numbers…) are read as well as JSON, and written as JSON; errors give the exact line and column and the editor jumps there. Key order is kept everywhere.

  • Format: pretty-print (two or four spaces, or tabs), minify or validate; Sort keys orders every object's keys. Validate says when the text is JSONC or JSON5 rather than strict JSON.
  • Tree: fold and open objects and arrays, copy any value's path (.spec.containers[0].image), and search keys, paths and values; a click on a match copies its path. A document over 2 MB shows what it holds (objects, arrays, keys, depth) instead of a tree.
  • Convert: JSON to YAML and YAML to JSON; anchors are resolved, several YAML documents become an array, and Swap sends the result back the other way.
  • Diff: two documents (paste, open or drop files) compared by path: added, removed, changed, or a type that changed. Key order and formatting don't count; 1.0 and 1 are the same.
  • Paths: every value as path = value, empty objects and arrays included, and back from such lines.
  • Schema: a JSON Schema (draft 2020-12) every sample fits, from one document, several, or JSON Lines: types, properties in the order first seen, required keys, array items, and formats such as date-time, email and uuid.
  • Query: a jq filter, with examples to start from; no environment, at most 1000 results, 5 seconds.

The same from the command line: codec json (see the CLI reference).

JWT#

Decodes the header and claims, shows registered claims with their meaning (iss issuer, exp expires…), times as dates with "in 3 hours" or "expired yesterday", and a validity badge. The signature is not verified — codec has no keys — and says so.

For other logs — JSON, ECS, logfmt, klog, text from services, pods and pipelines — use the Log viewer.

Ansible log#

Paste a whole log from a pipeline, or drop or open a log file (up to 64 MB). CI timestamps (GitLab, GitHub, Azure DevOps), wrapper prefixes (Packer, Compose), colour codes, shell output and several playbook runs in one log are all fine; codec learns wrapper prefixes from the log instead of knowing them in advance. Each log gets a tab of its own, as in Smart paste, so a failed run and a passing one can stay open side by side: + (or Alt T) for a new tab, × or a middle click (or Alt W) to close, a double click to rename. A tab is named after its file or the first run's playbook (site.yml), else Log 1, and its name turns red when the log has failures; each keeps its own selection, filter and host. The playbook map colours from the log in the current tab. It shows:

  • a summary: runs, hosts, tasks, duration, counts from the recap, and a verdict when the outcome isn't Ansible's alone ("Ansible succeeded; the output after it mentions errors", "stopped before its recap");
  • an outline of runs, plays and tasks with their status and duration, and the other output between them (CI steps, shell commands) as blocks with their error count. Filter by Failed, Changed, Skipped or All, pick a host, or search; arrow keys move through it. The first failure is selected when a log opens;
  • for the selected task, each host's result: failures a rescue caught and ignore_errors failures are told apart from real ones, as are unreachable hosts, retries, loop items and no_log output. Each result opens in the single-task view: probable cause, key fields, stdout/stderr with errors highlighted, and with a folder open Defined in (see Ansible);
  • for a run, its PLAY RECAP as a table, and its warnings.

Durations come from a timer callback (profile_tasks) when the run used one, otherwise from the CI timestamps. One task with one result — the TASK line, its task path and the result, even copied out of a Packer or Compose log — opens straight in the single-task view, as does a result line on its own. What you paste stays in the box; a file shows as a card instead. Alt C copies the outcome and the failures as text. On the command line: codec ansible log (see CLI).

Encode & hash#

Under Utilities in the sidebar. Five tabs; Home and the command palette list each one by name, and the tool reopens on the tab you used last.

  • URL — decode or encode percent-encoding. Encoding takes a single value (everything but letters, digits and -_.~ is escaped) or, with Whole URL, keeps a URL's : / ? # & = and existing %XX. + is a space for HTML form encoding. A URL is also shown as its parts and its query parameters as a table, repeats included; a password in the URL is never shown there.
  • Hex — hex to text and back. Decoding accepts spaces, colons, 0x and \x; bytes that aren't text show as \xNN. Encoding can put a space or colon between bytes, in upper case.
  • Hash — SHA-256, SHA-384, SHA-512, SHA-1 and MD5 of the exact text (spaces and line breaks count), in hex or base64. MD5 and SHA-1 are marked checksums only. HMAC takes a key. Paste a digest into Expected to see which one matches.
  • Checksum — drop or choose files (or pick one from the open folder) and each is hashed with SHA-256, SHA-384, SHA-512, SHA-1 and MD5 in one pass, as a stream, whatever its size; nothing is kept. Paste the checksum a download page gives (hex in any case, with or without colons, or base64) or a whole checksums file (sha256sum or BSD lines) and each file shows whether it matches; the algorithm follows from the digest's length. Files a checksums file names but you haven't added are listed, and Check in the open folder hashes them there. Copy gives sha256sum lines for a checksums file of your own.
  • Password — passwords for people, by the rules a site asks for: a length, which kinds of character (a–z, A–Z, 0–9, symbols) with at least so many of each, characters to leave out and no look-alikes; or a passphrase of random words with a separator, capitals and a digit if asked. Presets cover the usual cases (strong, a 14-character policy, no symbols, a 6-digit PIN, passphrases). The strength is shown in bits, counted exactly for the rules (an attacker who knows them gains nothing), with how long ten billion guesses a second would take; Hide masks it while you share your screen. Each choice is drawn from the operating system's secure random source without bias; shown once and never stored. Passphrase words come from the EFF large word list (7,776 words, 12.9 bits each) by the Electronic Frontier Foundation, CC BY 3.0 US.
  • Secrets — random secrets by length and character set (symbols leave out quotes, backslash, backtick and space, so a secret pastes into YAML or a shell as is), or random bytes as hex or base64, with their strength in bits; or placeholder commit SHAs shaped like git commit ids (40 hex characters, the 7-character short form, or 64 for SHA-256 repositories). Up to 100 at a time.
  • UUID — version 4 (random), 7 (starts with the time, so newer ones sort last: good database keys), or 5 and 3 (the same UUID every time for a namespace, such as DNS or URL, and a name), up to 1000 at a time, written in lower or upper case, without hyphens, in braces or as urn:uuid:. Read a UUID shows its version, variant and, for versions 1, 6 and 7, when it was made; a ULID is read too, with its time and its 128 bits written as a UUID.
  • htpasswd — a bcrypt user:$2y$… line for nginx ingress or Traefik basic auth, with the kubectl command to store it; Check tests a password against a line. The dice button suggests a strong password.

Everything is computed on this machine from the operating system's secure random source where randomness is needed; nothing is stored. On the command line: codec url, hex, hash, checksum, secret, uuid, sha and htpasswd (see CLI).

Network#

Under Utilities. Everything is worked out on this machine: nothing is looked up on the network.

  • CIDR — one range in detail, IPv4 or IPv6: network, broadcast, first and last host, netmask, wildcard, how many addresses and hosts, and what kind of range it is (private, shared carrier-grade NAT, documentation, link-local, public…). Type 10.0.0.0/16, an address and netmask, or one address; 10.0.0.5/24 shows the range it is in. Split it into subnets of any length, and check whether an address is inside. Overlaps takes a list, one range per line with # names, and marks the ranges that share addresses: the check to run before peering VNets or VPCs, or picking pod and service ranges.
  • IP — an address as a decimal number, hex and binary, IPv6 written out in full, IPv4-mapped IPv6, and its reverse-DNS name. It reads numbers too: 167772161, 0x0a000001.
  • HTTP — curl → fetch turns a curl command (from a terminal, docs or your browser's Copy as cURL, quotes and line continuations included) into JavaScript fetch, a JSON body as JSON.stringify of the value; fetch → curl goes the other way. What can't be carried over (a file to attach, a proxy, -k, a variable in the fetch code) is said in a note under the result. Nothing is sent. Status codes explains a code, its usual cause and whether to retry; type a number, its first digits (5 for every 5xx) or words such as gateway or rate limit.
  • URL builder — paste a URL to fill in its parts and its query parameters as a table, or type them; change, add or remove parameters and copy the URL put back together, each part escaped as it needs.

On the command line: codec cidr, codec ip, codec url build, codec curl and codec http status (see CLI), and codec case for Case & names.

Text & data#

Under Utilities.

  • Text diff — two texts compared line by line: paste or type them, or drop a file on either side (or open one). Changed lines show side by side with the changed characters marked, or as a unified patch to copy; the arrows go from change to change. Ignore whitespace and Ignore case loosen what counts as a change, and the swap button turns the comparison round. For files in the open folder, Helm renders and YAML compared by meaning, use Compare.
  • Case & names — a name or phrase in camelCase, PascalCase, snake_case, kebab-case, CONSTANT_CASE, dot.case, Title, Sentence, lower and path case, each with Copy. Words split at separators and case changes, and acronyms stay whole: getHTTPResponse is get · HTTP · Response. Name rules checks it as a Kubernetes name (DNS-1123 label and subdomain), a label value, an environment variable and a Helm release name (53 characters at most), says what breaks each rule, and offers a name that passes.
  • CSV & TSV — paste delimited text to see it as a table. The delimiter (comma, tab, semicolon or pipe) and whether the first row names the columns are guessed, and can be chosen instead; quoted fields may hold the delimiter, quotes and line breaks. Each column shows its type (integer, number, boolean, date or text); click a column to sort by it, filter the rows by any cell, and double-click a cell to copy it. The column button lists how many values each column has filled, empty and distinct; rows with more or fewer fields than the rest are counted. Copy gives the rows shown as TSV, ready for a spreadsheet. Convert writes the table as JSON, JSON Lines, YAML, a Markdown table (number columns right-aligned), CSV or TSV; Typed values makes numbers, booleans and null by each column's type, so a ZIP code such as 007 stays text. JSON → CSV goes the other way: an array of objects becomes one column per key, nested values written as JSON. The viewer shows the first 100 000 rows; conversions use them all. On the command line: codec csv (see CLI).
  • Test data — rows of made-up data from columns you pick (start from users, orders or servers, add, rename or remove columns): ids, UUIDs, names, emails, usernames, phones, companies, cities, country codes, IPv4 and IPv6 addresses, URLs, integers and numbers in a range, booleans, dates in a range, a choice of your own values, lorem words and sentences, each with a share of rows left blank. Names, emails and usernames in a row belong to one made-up person. Written as JSON, NDJSON, CSV, YAML or SQL INSERT statements, up to 10 000 rows. Nothing reaches a real person or host: emails use example.com, .org and .net, IPs the documentation ranges (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24, 2001:db8::/32), phones 555-01xx. Lorem ipsum gives words, sentences or paragraphs. A seed gives the same output again, for tests that must not change; pin the one a run used to keep it. On the command line: codec fake.

Time#

Under Utilities, with four tabs. Each has its time zone at the top (type to pick one); Timestamp and Formats start in this machine's zone, Cron in UTC, as GitHub Actions and Azure Pipelines run schedules.

  • Timestamp — type or paste an epoch number or a date on the line at the top; the answer is below it. The unit of a number is told by its size: up to 11 digits are seconds, then milliseconds, microseconds and nanoseconds. Dates are read in the usual layouts (ISO 8601, HTTP and email dates, access logs); one without a zone is read in the chosen zone. The answer shows Unix seconds and milliseconds, UTC, the chosen zone with its offset, a readable form, how long ago or how soon, the HTTP date and the ISO week, each with a copy button. Now fills in the current Unix timestamp.
  • Zones — a time in several zones at once: leave the line empty for now, or type 14:00 (today in the zone at the top), a date or an epoch number. Each zone shows its time, date, abbreviation and offset, whether daylight saving is on, +1 day when its date differs, and its next clock change. Add zones by name; they are remembered. Working hours lays each zone's hours under the first zone's day, marks 9 to 17, and names the hours when everyone is at work: the times to book a meeting.
  • Formats — one moment written every standard way: RFC 3339 (with milliseconds and nanoseconds), ISO 8601 basic, ISO week and ordinal dates, RFC 2822 (email), the HTTP date, SQL/log style, and Unix seconds, milliseconds, microseconds and nanoseconds, each with Copy. Format strings shows the common shapes with the format string for Go, Java, Python, .NET and JavaScript (click one to copy it), with the traps noted: Python's %:z needs 3.12, .NET's zzz writes a colon.
  • Cron — type an expression, pick a preset, or build one: every N minutes, hourly, daily, weekly on chosen days, or monthly, in every month or chosen months. Under the expression, one cell per field shows what you typed, the field's name and what it means; click a cell to select that field in the expression. The schedule shows in plain words ("Every 15 minutes, from 02:00 to 06:59, Monday to Friday"), with the build form and the next 10 runs side by side below. A typed expression fills the form when it fits. Standard 5-field cron, @daily-style shortcuts and a CRON_TZ= prefix are read. When both day fields are set (1 12 2 5 5), a day matching either runs, as in Kubernetes — the 2nd of May and every Friday in May — and a note says so. A run that a daylight-saving change skips is named. Quartz (seconds, ?, L, W, #) and Jenkins (H) expressions are recognised and named as unsupported.

On the command line: codec time (--in for other zones, --formats) and codec cron (see CLI).

Regex#

Under Utilities: a tester and an explainer on one screen. Type a pattern and some test text; matches light up in the text as you type.

  • Style: Go (RE2), Go's own regular expressions, which run in linear time but have no lookarounds or backreferences; or Python / .NET / JS, with lookahead and lookbehind, backreferences, atomic groups and Python's (?P<name>…). A test in that style stops after 2 seconds if the pattern backtracks badly, and says so. When RE2 refuses a pattern the other style takes, the error says so and Switch changes style.
  • Flags as toggles: i ignore case, m ^ and $ at line breaks (on by default), s . matches line breaks, x ignore whitespace (Python / .NET / JS). All matches off finds only the first.
  • Matches: each match with its line and capture groups, numbered and named; click one to select it in the text, hover a group to light up what it captured in every match. Up to 1000 matches.
  • Explanation: the pattern part by part in plain words ("One or more times, as few as possible (lazy)", "Group 1, named "year""). Hover a part to find it in the pattern, and a group to see what it matched.
  • Replace: type a replacement under the pattern ($1, ${name}, $0; Python's \1 and \g<name> work too; $$ is a dollar sign, and a group the pattern doesn't have stays as written) and see the result.
  • Group numbers: in Go's style groups are numbered in order. The Python / .NET / JS style numbers them as .NET does — named groups after the unnamed ones — so refer to a named group by its name there.

On the command line: codec regex (see CLI).

QR code#

Under Utilities, with two tabs. Everything happens on this machine; nothing is stored, and no camera is used.

  • Make — a code for text or a link; a Wi-Fi login a phone joins by scanning (network name, password, security, hidden networks; special characters escaped); or an authenticator setup link for TOTP (issuer, account, a base32 secret or a new random one, 6 or 8 digits, 30 or 60 seconds). Choose how much damage it survives, from level L (7%) to H (30%, enough for a logo on top). The preview shows the code and the text it holds (secrets hidden until you ask); save it as PNG or SVG, which stays sharp at any size.
  • Read — drop, paste (Ctrl+V) or choose an image with a QR code: a photo, a screenshot, PNG, JPEG, WebP, GIF or SVG, light on dark too. The text is shown with its parts: a link's host, a Wi-Fi network and password, an authenticator's issuer, account and secret, an email address or phone number.

On the command line: codec qr draws a code in the terminal or saves it with -o, and codec qr read reads one (see CLI). Codes are made with boombuler/barcode and read with gozxing, both MIT.

Colour#

Under Utilities, worked out in the browser; nothing is stored or sent.

  • Colour — type or paste a colour written any common way (#4f46e5, #abc, #4f46e580, rgb(79 70 229), hsl(243 75% 59%), hsv(…), oklch(51% 0.23 277), or one of the 148 CSS names), or click the swatch to pick one. It is shown as HEX, RGB, HSL, HSV and OKLCH, each with Copy, with its CSS name or the nearest one (≈). A colour that doesn't read leaves the last one on screen.
  • Contrast — the colour as text on a background of your choice: the WCAG 2 ratio (1:1 to 21:1) and the checks it passes: text AA (4.5:1) and AAA (7:1), large text AA (3:1) and AAA (4.5:1), and icons and borders (3:1); a translucent colour is laid over the background first. A sample shows large text, body text and an outline; swap with Alt S.
  • Shades — a scale from 50 to 950, as design systems name them, made in OKLCH so the steps look even. Click one to copy it, double-click to use it.

From the command line#

Input comes from an argument or from standard input.

codec auto '{"name":"codec"}'          # detect and transform
kubectl get secret db -o jsonpath='{.data.password}' | codec b64 decode
codec b64 encode 'any text at all'     # --url for the URL-safe alphabet
codec json pretty '{"a":{"b":1}}'      # --indent to customise; json min, json validate
codec json validate '{"a":}'           # exit 1 and "line 1, column 6"
codec jwt decode "$TOKEN"              # does NOT verify the signature
codec auto < failed-task.log           # Ansible -vv analysis
codec watch                            # transform recognisable clipboard content in place

-c on any command also copies the output to the clipboard. Windows PowerShell 5.1 strips inner double quotes from native arguments; pipe instead ('{"a":1}' | .\codec.exe auto) or use PowerShell 7.
