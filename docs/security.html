Security and privacy

codec runs a web server on your machine that can read your repositories. That deserves care. Here is what it does, what it never does, and why web pages you visit can't use it.

What codec promises#

  • It never writes to the folders it opens. Files are opened for reading only. What-if edits live in the browser tab. Generated files are text to copy or a zip your browser saves.
  • Nothing leaves your machine. No telemetry, no analytics, no accounts. The UI loads no third-party resources. The only outbound requests are downloads of public JSON schemas, which you can turn off (offline mode).
  • Nothing you paste is stored. The encode/decode tools keep input in memory only.
  • No config files in your repositories. Settings live in your user profile.

The local server#

ProtectionWhat it stops
Binds to 127.0.0.1 by defaultOther machines on your network can't connect. --host exists only for containers.
Host header must be a loopback nameDNS rebinding: a web page whose domain is made to resolve to 127.0.0.1 can't talk to codec, because its requests carry its own host name.
A random token per run, required on the APIOther pages and programs can't call the API without it; it is only in the page codec serves you, and changes every time codec starts.
Foreign Origin rejected on state-changing requestsCross-site form posts and scripts on other sites.
Paths validated and read through a confined root../ tricks and symlinks that point outside the open folder are refused, so the API can't be used to read other files.
Request size limits and cancellationOversized requests are refused; requests stop when the page moves on.

Docker#

The image is distroless (no shell or package manager) and runs as a non-root user. Mount repositories read-only (:ro) and publish the port on 127.0.0.1 only (-p 127.0.0.1:8765:8765), so the extra safety of the container adds to codec's own.

Secrets in your files#

  • Kubernetes Secret values are masked on cards until you reveal them; decoding happens locally.
  • GitHub secrets.* references are shown by name only.
  • Compose variables come from .env and what-if values, not from your shell's environment — so a secret in your environment never appears in the view.
  • The JWT tool decodes tokens locally and never verifies signatures against remote keys.

Reporting a vulnerability#

Please don't open a public issue for a security problem. Use GitHub's private vulnerability reporting for the repository, with steps to reproduce and the version (codec version).
