Design language

codec looks and behaves like a professional developer tool — calm, dense and precise, closer to Linear or VS Code than to a marketing site. This page describes the rules every screen follows. The same rules, with implementation detail, are in design/design-language.md for contributors and agents.

Principles#

PrincipleIn practice
InstantLocal operations answer in under 100 ms. While something loads, the layout stays put and shows placeholder blocks (skeletons), never spinners.
Keyboard-firstEvery action has a shortcut or a palette entry. Focus is always visible when using the keyboard.
Never lose stateTabs keep their state; what-if edits last until reset; the layout survives reloads.
Explain, don't just flagEvery problem says why it matters, how to fix it, and links to the spot.
Copy everywhere it helpsPaths, values, rendered documents, diffs, effective configurations.
HonestWhat codec can't know (run-time values, remote files) is shown as such, never guessed.

Colour#

codec is dark only. Depth comes from stepping surfaces, not from shadows; the one soft shadow is kept for popovers and dialogs. Every colour is a named token; components never use raw colours.

Accent and status#

--accent
focus, selection, primary
--ok
--warn
--err

Each status colour has a soft variant (14% opacity) for backgrounds such as badges and tinted lines. Severity is never shown by colour alone: an icon or a word goes with it.

Syntax and expressions#

key #8fb4ff
string #a8d68a
number #f2a66b
bool, null #d59bf6
comment #7a8497
anchor, alias #4fd1c5
template-time {{ }}
run time ${{ }}

Expressions get a faint tinted background of their own colour so they stand out inside YAML: amber for things evaluated before the YAML is used (Helm, Jinja), pink for things evaluated when it runs (GitHub, Argo, Azure). Values only known at run time are underlined with a dashed line in rendered output.

Type and spacing#

  • UI: Inter, 13 px with 1.5 line height; 11 and 12 px for small text; 14, 16, 20 and 28 px for headings.
  • Code: JetBrains Mono, 13 px with 1.55 line height. Both fonts are bundled; nothing loads from the internet.
  • Spacing: a 4 px scale (4, 8, 12, 16, 20, 24, 32, 48).
  • Radius: 4 px for inputs, 6 px for buttons, 10 px for panels and dialogs.
  • Controls: 28 px tall (24 px compact).
  • Motion: 120 ms ease-out, and none at all when the system asks for reduced motion.

Layout#

All panes resize and collapse, and their sizes persist. Lens views use a consistent three-part layout: a side panel of inputs and summaries, a main area (graph or list), and details for the selected item.

Components#

Every screen is built from one shared set: buttons (primary, secondary, ghost), icon buttons with tooltips, tabs, segmented controls, selects, toggles, search inputs, split panes, the tree (keyboard navigable, windowed for long lists), the code view (CodeMirror), the graph (automatic layout, pan and zoom, hover highlights neighbours), popovers, dialogs, toasts, badges with file-type logos, empty states and skeletons.

  • Icons: Lucide, 16 px, 1.75 stroke, in the current text colour.
  • Logos: the official marks of Kubernetes, Helm, Argo, GitHub Actions, GitLab, Azure Pipelines, Ansible and Docker, used only to label file types, in brand colours adjusted for contrast on dark surfaces.

States#

StatePattern
EmptyAn icon, one sentence of what goes here, and the action that fills it ("Open folder", "Try the sample").
LoadingSkeleton blocks in the shape of the content; small "Reading…" text only for refreshes of content already shown.
ErrorWhat failed in plain words, the reason if known, and a way forward ("Try again", a link to the line).
SuccessQuiet: a green check and a count ("No problems found"), never a modal.

Accessibility#

  • Text meets 4.5:1 contrast on its surface (muted text included, on every surface but pressed states).
  • A 2 px accent focus ring on keyboard focus, never removed without a visible replacement.
  • Every control has an accessible name; icon-only buttons have labels and tooltips.
  • Trees, lists, tabs and radio groups follow the WAI-ARIA patterns for keyboard use.
  • Reduced motion is respected.

Writing#

  • Plain, short sentences; sentence case for titles and buttons.
  • Say what happened and what to do: "Reusable workflow test.yml doesn't exist — paths are relative to the repository root."
  • Name things the way their tools do (values.yaml, needs, templateRef) and explain them on first use.
  • No exclamation marks, no blame, no jargon when a common word works.
